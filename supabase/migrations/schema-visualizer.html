🗄️ Entity Relationship Diagram (ERD)

แสดงความสัมพันธ์ระหว่าง 5 ตาราง — คลิกลากซูมได้ (จาก Mermaid)

🔗 ความสัมพันธ์ของตาราง

  • users 1:N → borrow_records (นักเรียนยืมหนังสือได้หลายเล่ม)
  • users 1:N → room_access_logs (เข้าใช้งานห้องสมุดหลายครั้ง)
  • books 1:N → borrow_records (หนังสือถูกยืมหลายครั้ง)
  • book_categories 1:N → books (ประเภทหนึ่งมีหลายหนังสือ)
  • users 1:N → borrow_records.handled_by (เจ้าหน้าที่ทำรายการ)

⚠️ Constraint / Logic ที่สำคัญ

  • ✅ available_copies ≤ total_copies (CHECK)
  • ✅ fine_amount ≥ 0
  • ✅ check_out_at ≥ check_in_at
  • ✅ Trigger ลด available_copies ตอนยืม / เพิ่ม ตอนคืน
  • ✅ mark_overdue_books() อัพเดต overdue ทุกคืน
  • ✅ student_id, book_code เป็น UNIQUE

1️⃣ Flow การยืมหนังสือ

เจ้าหน้าที่สแกนบัตร + สแกนหนังสือ → บันทึก borrow_records + ลด available_copies

📊 ตารางที่ถูกอัพเดตใน Flow นี้

🟢 anon (Public)

ไม่ต้อง Login
  • ✅ SELECT books, categories
  • ✅ INSERT room_access_logs
  • ❌ SELECT/INSERT users, borrow_records

🔵 authenticated

Login แล้ว
  • ✅ is_admin() → CRUD ทุกอย่าง
  • ✅ user ดู/แก้ไข ตัวเองได้
  • ✅ ดูประวัติยืม/เช็คอินของตัวเอง

🔴 service_role

ฝั่ง Server เท่านั้น
  • ✅ ข้าม RLS — ใช้ทำ Transaction
  • ⚠️ ห้ามใส่ใน Client Code เด็ดขาด
  • ใช้ใน Next.js Server Action

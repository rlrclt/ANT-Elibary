# Page Patterns — วิธีคิดเวลาจะประกอบหน้าใหม่

เอกสารนี้คือ "สมอง" ของสกิล ใช้ตัดสินใจว่าหน้าใหม่ที่ผู้ใช้ขอ ควรจัดวางองค์ประกอบแบบไหน โดยอิงจาก**ประเภทของหน้า** ไม่ใช่แค่ก็อปธีมสีมาแปะ

## ขั้นตอนคิดก่อนเริ่มออกแบบหน้าใหม่

1. **หน้านี้ประเภทไหนใน 4 กลุ่มด้านล่าง?** → เลือก layout skeleton ที่ตรงกลุ่ม
2. **ผู้ใช้จะเข้าหน้านี้เพื่อ "สำรวจ/เลือกดู" หรือ "โฟกัสตัดสินใจเรื่องเดียว"?**
   - สำรวจ/เลือกดูหลายรายการ → มี sidebar/filter, grid หนาแน่น, banner ได้
   - โฟกัสเรื่องเดียว → ไม่มี sidebar, ไม่มี banner, เน้น white space รอบ CTA
3. **มีข้อมูลที่ต้อง "เปรียบเทียบ" ไหม (ราคาก่อน-หลัง, อันดับ, คะแนน)?** → ถ้ามี ใช้ badge/สี ตามกฎในหมวด 6-7 ของ `components.md` อย่างเคร่งครัด
4. **หน้านี้ต้องมี footer แบบไหน** ตามกฎท้าย `components.md` ข้อ 12
5. **เช็ค responsive**: ทุก grid ต้องกำหนดอย่างน้อย 3 breakpoint (มือถือ/แท็บเล็ต/เดสก์ท็อป) ตามตารางใน `design-tokens.md` หมวด 4

---

## กลุ่มที่ 1: หน้ารายการ/สำรวจเนื้อหา (Listing / Browse)

**ตัวอย่าง**: หน้าแรก, หน้าหมวดหมู่ย่อย (เช่น "นิยาย Boy Love ทั้งหมด"), หน้าค้นหา, หน้าโปรโมชันรวม, หน้าผลการค้นหา

**โครงมาตรฐาน (บนลงล่าง)**:
```
Header (เขียว, sticky)
Secondary Nav (tabs/แท็บหมวดหมู่)
[ถ้ามีตัวกรองเยอะ: Sidebar หมวดหมู่ ทางซ้าย + เนื้อหาทางขวา]
  Banner Carousel (เฉพาะหน้าแรกจริงๆ หรือหน้าที่มีแคมเปญ — หน้าค้นหา/หน้าหมวดหมู่ย่อยไม่ต้องมี)
  Section 1 (ขายดี → ใช้ rank badge)
  Section 2 (มาใหม่ → การ์ดธรรมดา อาจมี % ลด)
  Section 3+ (ฟรี/โปรโมชัน/ตามบริบท)
Footer แบบเต็ม
```

**กฎเฉพาะกลุ่มนี้**:
- ถ้าเป็นหน้าหมวดหมู่เจาะจง (เช่น "นิยายวาย") ให้แทน "แถวเลื่อน section" ด้วย **grid เดียวยาว + pagination หรือ infinite scroll** และเพิ่มแถบ sort/filter ด้านบนกริด (เรียงตาม: ล่าสุด/ขายดี/ราคา/คะแนน — ใช้ dropdown style เดียวกับ dropdown หมวดหมู่ในค้นหา)
- ถ้าเป็นหน้าค้นหา (search results) ให้เพิ่มแถบสรุปผล ("พบ N รายการสำหรับ 'คำค้น'") เหนือกริด แทน section header ปกติ ไม่ต้องมี "ดูทั้งหมด" เพราะนี่คือ "ทั้งหมด" อยู่แล้ว
- จำนวนคอลัมน์กริด: ใช้ตารางใน `design-tokens.md` หมวด 4 — ถ้ามี sidebar ให้ลดคอลัมน์เดสก์ท็อปเหลือ 4 เสมอ

---

## กลุ่มที่ 2: หน้ารายละเอียดสินค้า/เนื้อหาเดี่ยว (Detail / PDP)

**ตัวอย่าง**: หน้ารายละเอียดหนังสือ (ต้นแบบ), หน้ารายละเอียดผู้แต่ง/สำนักพิมพ์ (โครงคล้ายกันแต่สลับเนื้อหา), หน้าอ่านตัวอย่าง

**โครงมาตรฐาน**:
```
Header + Secondary Nav (แบบ breadcrumb-in-category ได้)
Breadcrumb (หน้าแรก > หมวดหมู่ > ชื่อสินค้า)
Content card ขาวใหญ่ 2 คอลัมน์ (md:flex-row):
  ซ้าย (1/3): ปกใหญ่ + badge ส่วนลด + ปุ่มแชร์โซเชียล
  ขวา (2/3):
    ชื่อเรื่อง + meta (ผู้แต่ง/สนพ./หมวดหมู่) + rating
    Price Box (เหลือง) พร้อมปุ่ม CTA คู่
    Info Grid (metadata)
    Synopsis/เนื้อหา (มี TW&CW ถ้าเนื้อหาละเอียดอ่อน, tags ท้ายเนื้อเรื่อง)
    Info/Alert box เสริม (ถ้ามีข้อมูลนอกเหนือ เช่น "มีขายที่อื่น")
Footer แบบเรียบ
```

**กฎเฉพาะกลุ่มนี้**:
- **ห้ามใส่ sidebar หมวดหมู่และ banner carousel** — จะแย่งความสนใจจาก CTA ซื้อ
- ปุ่ม CTA primary ("ซื้อเลย"/"อ่านต่อ") ต้องอยู่ "เหนือ fold" เสมอ (ก่อน info grid) แม้บนมือถือ
- ถ้าเนื้อหามีความละเอียดอ่อน (เช่น TW&CW ในต้นแบบ) ให้แสดงคำเตือนแบบสั้น กระชับ ก่อนเนื้อเรื่องยาว ไม่ซ่อนเป็นค่าเริ่มต้น
- Related/แนะนำเพิ่มเติม (ถ้าต้องมี) ให้ใส่เป็น section รูปแบบกลุ่มที่ 1 ต่อท้าย "ก่อน" footer เท่านั้น ไม่แทรกกลางเนื้อหา

## กลุ่มที่ 3: หน้าธุรกรรม (Transactional)

**ตัวอย่าง**: ตะกร้าสินค้า, checkout, หน้ายืนยันการชำระเงิน, หน้าใส่โค้ดส่วนลด

ต้นแบบไม่มีหน้านี้ตรงๆ แต่ให้ยึดหลักเดียวกับกลุ่มที่ 2 (โฟกัสเดี่ยว) บวกกฎเสริม:

**โครงแนะนำ**:
```
Header แบบย่อ (ตัดช่องค้นหาออกได้ ถ้าต้องการลดสิ่งรบกวนระหว่างชำระเงิน) + progress indicator (ตะกร้า → ที่อยู่/ชำระเงิน → เสร็จสิ้น) ใช้สีเขียวแบรนด์ไฮไลต์ขั้นตอนปัจจุบัน
เนื้อหา 2 คอลัมน์ (เดสก์ท็อป): รายการสินค้า/ฟอร์ม (ซ้าย, กว้างกว่า) + สรุปยอด sticky (ขวา, ใช้กล่องพื้นเหลืองอ่อนแบบ Price Box เพื่อความสม่ำเสมอ)
ปุ่ม primary "ดำเนินการต่อ/ชำระเงิน" พื้นเขียว เต็มความกว้างการ์ดสรุปยอด
Footer แบบเรียบ (ไม่มี banner, ไม่มี social links เพื่อลด distraction ตอนจ่ายเงิน)
```

**กฎเฉพาะกลุ่มนี้**: ห้ามมี banner/carousel/section แนะนำสินค้าอื่นแทรกระหว่างขั้นตอนชำระเงิน (เพิ่ม friction+เสี่ยง cart abandonment) — จะแนะนำสินค้าเพิ่มได้เฉพาะ "ก่อน" กดเข้าสู่ checkout เท่านั้น (เช่นในหน้าตะกร้า)

---

## กลุ่มที่ 4: หน้าบัญชีผู้ใช้ (Account / Profile)

**ตัวอย่าง**: โปรไฟล์, ประวัติการสั่งซื้อ, รายการโปรด/Wishlist, ตั้งค่า

ต้นแบบไม่มีหน้านี้ตรงๆ ให้ยึดโครงกลุ่มที่ 1 (มี sidebar) แต่เปลี่ยนเนื้อหา sidebar จาก "หมวดหมู่หนังสือ" เป็น "เมนูบัญชี" (โปรไฟล์/ประวัติการสั่งซื้อ/Wishlist/ที่อยู่จัดส่ง/ออกจากระบบ) โดยใช้โครง sidebar เดียวกัน (หัวเขียว + list แบ่งเส้นบาง) เพื่อความคุ้นเคย

**กฎเฉพาะกลุ่มนี้**:
- รายการ Wishlist ใช้ Book Card แบบเดียวกับหน้ารายการ แต่เพิ่มปุ่ม "นำออก" มุมขวาบนแทนป้ายส่วนลด (ถ้าไม่มีส่วนลด)
- หน้าประวัติการสั่งซื้อ ใช้ Info Grid style (label-value) ต่อหนึ่งออเดอร์ ไม่ใช่ book card grid

## Checklist ก่อนส่งงานหน้าใหม่ทุกครั้ง

- [ ] Header/logo/สีเขียวแบรนด์ตรงกับ `design-tokens.md` เป๊ะ (ไม่เพี้ยนเฉด)
- [ ] ฟอนต์ Noto Sans Thai โหลดถูกต้อง, ไอคอนเป็น Phosphor ทั้งหมด
- [ ] เลือก layout skeleton ตรงกับกลุ่มหน้า (1 ใน 4 กลุ่มข้างบน) ไม่ผสมองค์ประกอบข้ามกลุ่มโดยไม่มีเหตุผล (เช่น อย่าใส่ banner ในหน้า checkout)
- [ ] Badge/ป้ายบนการ์ดหนังสือใช้ตรงความหมาย (rank เฉพาะ "ขายดี", ribbon เฉพาะเน้นเล่มเด่น, % เฉพาะมีส่วนลดจริง)
- [ ] Responsive ครบ 3 breakpoint อย่างน้อย, ทดสอบว่า sidebar/banner ซ่อนถูกจุดบนมือถือ
- [ ] Footer เลือกแบบถูกต้องตามความลึกของหน้า (เต็ม vs เรียบ)
- [ ] สีแดงใช้เฉพาะราคา/ส่วนลด/เร่งด่วน ไม่ใช้เป็นปุ่ม action หลัก
